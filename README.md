# UI-автотесты для practice-automation.com

Проект автотестов для страниц с упражнениями сайта https://practice-automation.com/:

- Календарь — https://practice-automation.com/calendars/
- Модальные окна — https://practice-automation.com/modals/
- Рекламные окна — https://practice-automation.com/ads/
- Форма (задание №5) — https://practice-automation.com/form-fields/

**Стек:** Python 3.12+, Selenium 4, Pytest, Allure. Подход: **Page Object Model**.
Браузеры: Chrome (по умолчанию) и Firefox; драйверы скачиваются автоматически (`webdriver-manager`).

## Структура проекта

```
├── conftest.py              # фикстура driver (Chrome/Firefox, --headless), скриншот в Allure при падении
├── pytest.ini               # настройки pytest, маркеры, папка allure-results
├── requirements.txt
├── pages/                   # Page Object Model
│   ├── base_page.py         # общие методы: ожидания, click, type_text, проверки видимости
│   ├── calendars_page.py
│   ├── modals_page.py
│   ├── ads_page.py
│   └── form_fields_page.py  # список "Automation tools" + форма (задание №5)
└── tests/
    ├── test_calendars.py
    ├── test_modals.py
    ├── test_ads.py
    └── test_form_fields.py
```

Локаторы и действия описаны только в `pages/`, в тестах — только сценарии и проверки.

## Установка и запуск

Windows (PowerShell), команды выполнять по одной:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m pytest
```

Linux / macOS:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m pytest
```

Полезные варианты запуска:

```bash
python -m pytest --headless              # без окна браузера
python -m pytest --browser=firefox       # Firefox
python -m pytest -m positive             # только позитивные
python -m pytest -m negative             # только негативные
python -m pytest tests/test_calendars.py # один файл
```

Нужен установленный Chrome (или Firefox для `--browser=firefox`). Полный прогон занимает несколько минут — на странице рекламы есть обратный отсчёт.

## Отчёт Allure

Результаты пишутся в `allure-results` автоматически (см. `pytest.ini`). Чтобы открыть отчёт, нужен Allure Commandline (`npm install -g allure-commandline`, нужен Node.js, либо `scoop install allure` на Windows):

```bash
allure serve allure-results
```

Отчёт показывает, какие тесты запущены и с каким результатом; у тестов и шагов осмысленные названия (`@allure.title`, `allure.step`); к каждому упавшему тесту автоматически прикладывается **скриншот** (хук `pytest_runtest_makereport` в `conftest.py`).

## Тестовые сценарии

### Календарь (`tests/test_calendars.py`) — 9 позитивных, 5 негативных

Позитивные:
1. Страница открывается, видны поле даты и кнопка Submit.
2. В поле можно ввести корректную дату (формат ГГГГ-ММ-ДД).
3. Отправка корректной даты показывает сообщение об успехе.
4. Сегодняшняя дата принимается.
5. Дата високосного года (2024-02-29) принимается.
6. Дата далёкого будущего принимается.
7. Дата далёкого прошлого принимается.
8. Поле можно очистить и заполнить заново.
9. Повторная отправка (после перезагрузки страницы) с другой датой проходит успешно.

Негативные:
1. Отправка с пустым полем не показывает успех.
2. Отправка некорректных значений (параметризовано: произвольный текст, несуществующие месяц/день, неверный формат) не показывает успех.
3. Ввод из одних пробелов не считается валидной датой.

### Модальные окна (`tests/test_modals.py`) — 8 позитивных, 4 негативных

Позитивные:
1. Страница открывается, видны кнопки обоих модальных окон.
2. Простое модальное окно открывается и показывает текст.
3. Простое модальное окно закрывается крестиком.
4. Модальное окно с формой открывается.
5. Форма принимает Name, Email и Message.
6. Отправка формы с валидными данными показывает сообщение об успехе.
7. Окно с формой можно открыть повторно после закрытия.
8. Поле Message принимает длинный текст.

Негативные:
1. Пустое обязательное поле Name браузер помечает как невалидное.
2. Некорректный email браузер помечает как невалидный.
3. Пустая форма: обязательное поле Name невалидно.
4. Текст простого модального окна не виден до его открытия.

Примечание: JS сайта отправляет форму и показывает «Thank you for your response» независимо от содержимого полей, поэтому текст об успехе нельзя использовать как негативный признак. Вместо него проверяется HTML5-валидация браузера (`checkValidity()`), опирающаяся на реальные атрибуты `required` и `type="email"`.

### Рекламные окна (`tests/test_ads.py`) — 7 позитивных, 3 негативных

Позитивные:
1. Страница открывается, видна инструкция про рекламу.
2. Рекламное окно появляется автоматически после отсчёта.
3. В рекламном окне ожидаемый текст.
4. Рекламное окно закрывается.
5. После перезагрузки страницы реклама появляется снова.
6. После закрытия рекламы навигация на главную работает.
7. В первый момент загрузки рекламы ещё нет (до конца отсчёта).

Негативные:
1. Повторное закрытие рекламы подряд не приводит к ошибке.
2. После закрытия текст рекламы не виден.
3. На главной странице рекламного окна нет.

### Форма — задание №5 (`tests/test_form_fields.py`) — 3 теста

1. Список «Automation tools» читается со страницы (не пустой, содержит Selenium).
2. **Поле Message заполняется списком из раздела «Automation tools»**: элементы списка читаются средствами Selenium, преобразуются в текст, соединяются через запятую и вводятся в Message; проверяется, что в поле именно эта строка; затем форма отправляется.
3. Порядок инструментов в Message совпадает с порядком на странице.
